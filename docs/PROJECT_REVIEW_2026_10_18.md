# 项目审查与优化建议（2026-10-18）

审查对象：当前源码及 v2.6.6 交付流程。用户已确认公司环境测试正常。本次只阅读代码、运行现有代码检查命令并整理建议，没有修改匹配规则、网页或旧发布包，也没有读取公司产品目录。

结论：当前核心查询流程适合继续内部试用，下一阶段重点是防止工作丢失、处理大批量数据和规范部署更新。以下将代码确认的问题与尚待实测的性能风险分开列出，不把建议当成已经实施的功能。

## 近期优先

### 1. 新目录校验成功后再替换旧目录

已确认：导入事件一开始就清空当前 catalog、A/B 结果和勾选，之后才检查文件名、数量并读取数据。误选、损坏或读取失败会使原先可用的工作状态丢失，需要重新导入及查询。

建议：先在候选目录中读取并校验，成功后一次性切换，失败时保留原目录和查询。切换过程中关闭新查询或清楚标注旧结果来自旧目录，避免新旧数据混淆。验收重点是坏文件不能破坏已有工作、成功换库不保留旧目录的候选。

依据：[translator.ts](E:/WaPJTS/PNrep/src/official-preview/translator.ts:354)。

### 2. 批量查询的性能和可取消性

代码确认的开销：每次匹配重新统计整库 blockedRecords；料号查询使用 records.filter 全库查找；空结果诊断逐记录逐条件统计；“显示更多”重新运行该条查询。页面没有 Worker；即使详情折叠，productCard 仍立即创建全部详情、链接和来源节点。每行查询结束虽让出事件循环，但单次扫描和大组渲染仍在主线程。

这是性能风险，不等于已经在公司电脑复现卡顿，也没有实测完整115098条目录的延迟和内存。本次不报告未经测量的提速倍数。

建议顺序：建立按完整料号索引、缓存目录级计数和分类；同一查询扩展显示时复用匹配结果；点击详情时才生成详细节点；对大量可见结果分段/虚拟渲染；最后按公司压力测试决定是否把解析/匹配放到Worker，并增加取消查询。避免在优化时改变匹配与导出语义。

依据：[translate.ts](E:/WaPJTS/PNrep/src/engine/official/translate.ts:61)、[matcher.ts](E:/WaPJTS/PNrep/src/engine/official/matcher.ts:41)、[translator.ts](E:/WaPJTS/PNrep/src/official-preview/translator.ts:410)。

### 3. 两个数据文件的版本绑定

当前网页校验结构、数量、来源路径和问题计数，但没有用产品文件内容校验值绑定汇总文件。不同运行的两份文件若元信息恰好一致，现有校验不足以证明它们确实来自同一次整理。这不是认定公司当前数据混用了。

已有完整目录准备报告包含原始、汇总和产品文件SHA256，建议复用这些信息建立datasetId或在汇总内记录产品文件hash，网页导入时验证并展示。内容校验用于识别错配/改动，不能证明厂商真实性或官网覆盖完整。

依据：[catalog.ts](E:/WaPJTS/PNrep/src/engine/official/catalog.ts:36)、[Prepare-MurataFullCatalog.template.ps1](E:/WaPJTS/PNrep/scripts/Prepare-MurataFullCatalog.template.ps1:77)。

## 正式部署前

### 4. 确定目录加载与更新方式

当前目录只在页面内存，刷新要重新选择两个文件，适合当前单文件验证阶段。正式内网使用可由公司批准的内网数据服务提供当前目录版本，或另行设计用户可清除的本机缓存；数据读取和匹配放在哪一侧，应先按公司电脑性能、使用人数和公司规定决定。不要把约182MB产品JSON塞进localStorage，也不要把公司目录发布到公开站点。

最低配套信息：网页版本、匹配规则版本、目录版本、来源文件时间/整理时间、记录数、校验值、更新内容和回退入口。整理时间不能显示成“官网最后更新时间”。自动更新属于后续设计，本次未创建定时任务或上传数据。

依据：[official.ts](E:/WaPJTS/PNrep/src/stores/official.ts:5)、[translator.ts](E:/WaPJTS/PNrep/src/official-preview/translator.ts:342)。

### 5. 补齐发布检查与统一打包

本次实际运行 npm run lint 失败：项目声明调用eslint，但当前依赖未提供该命令；也没有找到相应配置和CI流程。建议补齐后把类型检查、单元测试、H5/离线构建、升级脚本及少量关键浏览器回归串成发布检查。

现有多个版本分别复制打包/更新脚本，人工替换版本号、文件名和hash容易出错。建议抽出公共打包器，用单个发布清单描述版本与base。历史HTML和补丁需要保留原字节及校验值，不能为了整理文件夹而覆盖或删掉升级base。

浏览器回归优先覆盖：正常/替代/超高参考分组、AEC与应用约束、A/B和勾选保留、已选Excel、规格书二次选择、坏目录导入保护。现有引擎测试不能代替真实浏览器事件和公司环境验收。

依据：[package.json](E:/WaPJTS/PNrep/package.json:15)、[构建脚本](E:/WaPJTS/PNrep/scripts/build-height-reference-deliverables.mjs)。

代码路径确认：H5查询页通过v-if切换，离开会卸载共享查询UI；再次挂载只传入initialMode、initialInput和catalog，没有传入结果、选中项和完整A/B工作台状态。因此导航返回首页/知识库再回来时，没有完整恢复查询结果与勾选。本次没有用浏览器复现这一条，结论基于挂载/卸载和初始化接口检查。

这与公司单文件HTML内的A/B切换不同；后者已有保留行为，不应据此声称公司正在使用的功能坏了。

## 后续体验与维护

### 7. 让替代规则和结果更容易解释

为每条查询显示本次目录确定的相邻档位，例如容值22→27uF、电压6.3→10V、封装0201→0402，并解释被高度、AEC、应用、精度等条件排除的原因。例子只说明显示形式，不代表公司目录一定包含这些值。

可增加按正常/替代/参考/未匹配汇总及跳转，方便处理多行输入。Excel附上网页/规则/目录版本和查询条件，方便客户反馈后按同一版本追溯。精度收紧等新替代规则必须另行确认，不在此次审查中默默启用。

### 8. 知识库附件保存失败的提示

H5知识库把附件存到localStorage；容量不足/禁用时仅记录控制台警告，页面仍完成“资料已添加”的流程。资料可能只留在当前内存，刷新后附件无法恢复。该功能不在公司单文件工作台主流程内，优先级低于上面几项。

建议让持久化操作返回明确结果，保存失败时显示可重试提示；后续统一放到合适的本机存储或公司批准的资料服务。仍明确“参考资料不等于启用了解析规则”，当前界面已有这个说明。

依据：[knowledge.ts](E:/WaPJTS/PNrep/src/stores/knowledge.ts:111)、[knowledge.vue](E:/WaPJTS/PNrep/src/pages/knowledge/knowledge.vue:348)。
