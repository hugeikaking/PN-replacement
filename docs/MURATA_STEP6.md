第六步：将原始 Murata_MLCC.json 中的全部记录接入网页
适用于公司目前已成功升级的 v2.5.1。

本次范围
公司电脑上保留了原始 Murata_MLCC.json，因此先在公司本机整理这份文件中的全部 Products 记录。
本步骤不需要 API 密钥，不联网、不上传公司数据库，不需要公司 AI。
“全部记录”指所选来源文件的全部记录；不是已经核实官网当前最新全部产品。
原文件的下载日期、文件时间和官网覆盖范围仍需核对。以后有新下载的 MLCC 原始目录，可以同样另存整理。
其他产品类别暂时仍只归档，不作为 MLCC 直接导入。

需要取得的四个文件
1. Upgrade-PassiveTranslator-v2_6.ps1
2. Passive-PN-Translator-v2_5_1-to-v2_6.patch.json
3. Prepare-MurataFullCatalog.ps1
4. Convert-MurataDatabase-v3_4.ps1

通过公司允许渠道取得这些原始文件，保持名称和内容，不复制邮件正文重建文件。
如传递或执行受公司策略限制，由 IT 提供批准方式；不要修改安全策略。
第4个是已有 v3.4 转换器的原始副本，功能未改。整理工具要求它与本次提供的原件校验一致。
无需重新发送整个网页，也无需重传原来的八个分片。
文件夹内另有完整 v2.6 HTML，作为直接使用原件的备选；升级补丁成功时不用再取该大文件。

第一步：升级网页
把上述四个文件放在公司现有 v2.5.1 HTML 所在文件夹，在该目录打开 Windows PowerShell，运行：

& ".\Upgrade-PassiveTranslator-v2_6.ps1"

自动查找同目录与原始 v2.5.1 完全一致的 HTML，另存 Passive-PN-Translator-v2_6.html。
输入网页或补丁不一致时停止；已有新版不覆盖；原 v2.5.1 保留。
有多个同版网页或文件放在其他位置时，可明确指定：

& ".\Upgrade-PassiveTranslator-v2_6.ps1" -HtmlPath "D:\你的文件夹\Passive-PN-Translator-v2_5_1.html"

上面路径按实际修改。升级文件由 PowerShell 读取，不是通过网页的产品目录按钮导入。
v2.6 保留此前 CAP、CH、H 标称高度、RO 待确认、应用/标准/特征、A/B切换保留、清除、批量输入/导出。
规格 JSONL 文件上限由 128MB 提高到 512MB，记录数由 100000 提高到 250000；汇总上限仍为1MB。
逐块读取，超限时明确停止，不截取一部分冒充全量。浏览器仍需在内存中保存解析后的记录；
符合文件大小限制不能保证所有公司电脑都能流畅运行到上限，真实目录性能仍需公司测试。

第二步：整理全部来源记录
仍在同一 PowerShell 窗口运行：

& ".\Prepare-MurataFullCatalog.ps1"

弹出选文件窗口时，选择原始 Murata_MLCC.json。
不要选 normalization-summary.json，也不要选 normalized-products.jsonl。
工具会调用同目录的 v3.4 转换器，以 Full 模式遍历 Products 数组至结束，不依赖旧抽样目录。
整理过程中显示 Normalized ... products；大文件可能需要较长时间，请等到出现 Prepared folder。
只在本机读写。原始 JSON 以只读方式处理，前后核对 SHA256；旧样本和旧整理结果不覆盖。
相同料号且原记录完全相同的重复记录会去重；同料号内容冲突会隔离，全部冲突记录不能作为正常候选。
数值/文字冲突、缺失电压、NRND、未知生命周期等继续保留核查标记，不用猜测补齐。
应用、标准、安全证书、特征、标称/最大厚度仍按现有 v3.4 规则保留。

不使用选文件窗口时，也可明确指定：

& ".\Prepare-MurataFullCatalog.ps1" -InputPath "D:\你的目录\Murata_MLCC.json"

默认结果保存在桌面 Murata_Full_Catalog\normalize-日期时间-随机编号。
如需指定公司数据盘，添加 -OutputRoot "D:\Murata_Full_Catalog"。
不要关闭正在整理的窗口；失败结果的 normalization-summary.json 会标记未完成，不能导入。

第三步：查看本地报告
运行完成后，在输出的 Prepared folder 路径中，双击 full-catalog-preparation.html。
报告显示：
- 处理的原始记录数、去除完全相同重复后的产品数；
- 字段一致数、待核查数、冲突料号数；
- normalized-products.jsonl 的大小；
- 是否符合 v2.6 的文件大小和记录数限制；
- 系列分布、来源文件时间、来源/输出文件 SHA256。

另有 full-catalog-preparation.json 记录本次本地核对明细。
报告“符合限制”只表示文件大小和记录数符合上限；最终结构校验在网页导入时执行。
若超限，保留完整结果并告知维护者产品数和文件大小，不要截取数据。
原始处理数应等于整理产品数加完全相同重复记录数。不要把问题次数相加当作产品总数。
来源文件中记录很多但字段不全时，仍可能有大量待核查，不能自动当成规格已验收。

第四步：导入新的全量结果
打开 Passive-PN-Translator-v2_6.html。
在“导入产品目录”处同时选择本次同一新结果文件夹内：
- normalization-summary.json
- normalized-products.jsonl

不要混用旧2011条样本文件或另一次运行的文件。
成功后网页应显示新的产品总数，以及“已读完本次来源文件（不代表官网最新全部产品）”。
如果仍显示2011条，请核对是否打开了新网页、是否选了本次结果文件夹。
实际新数量以原始目录内容为准，不预先承诺具体条数。
原始 Murata_MLCC.json 和 full-catalog-preparation.json 都不直接导入网页。

第五步：统一测试
先设置“民用设备 / 工业设备”，或者全部应用选项都不选（默认仍是民用/工业），分别查询：

0402 100nF 16V X7R ±10%
0402 0.1uF 16V X7R ±10%
0201 4.7uF 2.5V X5R ±20%
008004 10pF 16V C0G ±2%

前两行单位等值，应用选择相同时，候选和总数应一致。
再分别选择汽车信息娱乐/舒适设备、汽车动力总成/安全设备，用同样的100nF条件核对应用分组。
候选数依实际原始目录、字段核验和应用范围而定，不保证每个范围都有结果。
没有找到时先查看诊断，不自动取消温度、精度、电压、标称高度或应用条件。
官网截图中的型号若原始来源文件不包含，也无法凭截图生成；需后续从官网/API更新来源。

料号→规格描述模式再输入：
CL05B104KO5NNNC
CL10B104KO8NNNC
C1608X7R1H104K080AA
MSASP063EB5475MFNA01

逐行核对已识别规格；不支持的竞争对手编码仍应明确报错，不补猜参数。
同一已识别描述复制到模式A，在相同应用条件下候选应一致。

客户原始七行继续测试：
CAP X6S 22uF +/-20% 10V CH0603 H1.0mm RO
CAP X5R 10uF +/-20% 6.3V CH0402 H0.7mm RO
CAP X6S 4.7uF +/-20% 10V CH0402 H0.7mm RO
CAP X5R 4.7uF +/-20% 6.3V CH0201 H0.39mm RO
CAP X5R 2.2uF +/-20% 6.3V CH0201 RO
CAP X6S 1uF +/-20% 6.3V CH0201 RO
CAP X5R 1uF +/-20% 6.3V CH0201 RO

H 是用户确认的标称高度，严格比较产品标称厚度；不接受更薄替代，不拿最大厚度代替。
RO 含义尚未知，这些查询全部只能标部分参数匹配，并明确提示RO待确认。
全量导入不会改变这个限制。

最后核对切换保留、手动清除、批量读表/导出、NRND和待核查分组、标准/特征与来源。
先返回一张 full-catalog-preparation.html 的结果截图，以及网页成功导入后的产品总数。
无需发送原始数据库、完整 JSONL、API 密钥或签名下载链接。
