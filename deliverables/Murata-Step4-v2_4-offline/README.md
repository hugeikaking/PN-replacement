# 第四步 v2.4：优先读取 JSON 应用、标准、特征

已依据用户提供的七张公司字段报告照片校准。照片覆盖原库前 20,000 条，不能证明全库只有这些字段或取值。没有获取或上传公司完整数据库。

## 在公司使用

1. 把 Convert-MurataDatabase-v3_4.ps1 放到公司允许的工作目录。若放在桌面，运行：

```powershell
powershell.exe -NoProfile -File "$env:USERPROFILE\Desktop\Convert-MurataDatabase-v3_4.ps1"
```

2. 默认只重新整理已有 Murata_Data_Check 中与原库版本一致的检查样本，不扩大产品范围，不是全库匹配测试。原库、旧检查、旧整理结果保留；新文件夹生成在桌面 Murata_Normalized。
3. 打开 Passive-PN-Translator-v2_4.html，导入这一次新结果文件夹里的 normalization-summary.json 和 normalized-products.jsonl。请选 v3.4 新结果，旧数据没有保存的分类字段不能靠更新网页补回来。

JSON 路径或检查目录不同，可加 -InputPath / -CheckDirectory；用法与先前转换器相同。网页兼容旧 v3.1/v3.3，但旧记录缺少字段时仍会明确标注系列资料参考。使用公司批准的文件传递方式，不更改后缀绕过邮件策略。

## 字段如何使用

| 功能 | JSON 字段 | 已确认格式 / 行为 |
| --- | --- | --- |
| 三类应用筛选 | Application | 字符串，逗号分隔多个“分类×描述”。民用×民用设备、工业×工业设备归入民用/工业；汽车I×汽车信息娱乐/舒适设备、汽车P×汽车动力总成/安全设备分别对应两个汽车按钮。 |
| 特征 | Specs.Characteristics | 字符串数组，保留原文展示：125℃、回流焊接、弯曲裂纹对策、啸叫对策/低失真等。原值有 High Q 才按原值显示；此次照片中未观察到 High Q，不能据 C0G 推定。 |
| 标准（安全规格） | 顶层 Standard | 照片显示“安全规格认证品”“符合日本国内电气用品安全法”；直接显示原记录，注明证书未核验。不从证书文件名猜认证机构或等级。 |
| 安全证书 | MediaFileUrls.SafetyCertificates | 字符串，可为空。非空 http/https 链接显示“安全证书（未核验）”，仅用户点击才打开，不自动下载。 |

医疗I/医疗eI的两种已观察标签保持在三类筛选之外；医疗单独适用的记录不误归为民用，不自动进入“应用未知”核查组。未知新标签/代码仍保留待确认。有明确选中应用的记录可以匹配，多选取并集。不勾选仍默认民用/工业；切换模式保留输入、结果与勾选，修改筛选后重新点击查询。

AEC-Q200 使用独立布尔字段及原有显示，不当作安全认证或动力总成适用性证明。Specs.TemperatureCharacteristicsCompliedStandard 中 EIA/JIS/MURATA 属温度特性标准，不放入安全规格栏。Standard 缺失时，先显示特征数组中已确认的安全文字；再使用明确标注的系列资料，不能当作单型号证书已核验。显式空特征数组不补成 High Q。
