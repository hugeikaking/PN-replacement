# v2.5.1 客户描述识别与公司电脑迁移

本次更新支持客户的 CAP / CH 封装 / H 标称高度描述，沿用已有 Excel/CSV 批量导入导出和应用筛选。产品目录范围没有扩大，不拼接新料号。

## 新增行为

- CAP 是电容描述标签，不作为产品参数；保留客户原输入以便核对。
- CH0603、CH0402、CH0201 分别按英制 0603、0402、0201 查询。仍支持裸封装代码和显式公制 1005M。页面会提示默认英制。
- +/-20% 原解析器已有支持，本次将其加入客户原始七条描述的回归测试，与 ±20% 相同。
- 根据用户确认，H1.0mm、H0.7mm、H0.39mm 表示标称高度，比较已有目录 spec.thicknessMm；不能用 thicknessMaxMm 代替，也不按“小于等于”查找。没有 H 时不加高度条件。
- RO 含义未确认。只识别这个完整词为“待确认要求”，不猜测为 RoHS、包装或其他认证。允许返回其余已识别参数的候选，但一律标为“部分参数匹配”，在页面和导出保留 RO 待确认提示；不能宣称全部条件已核验。其他未知词仍报错。
- 同一条出现不同封装、高度、电压等条件仍报错。缺少标称厚度的记录不能满足明确 H 条件。
- 无匹配诊断新增“标称高度”一行。候选导出的末尾新增“标称高度(mm)”和“最大高度(mm)”两列，区分这两个值；既有列顺序不变。

## 公司电脑使用

1. 通过公司允许的文件渠道取得 Passive-PN-Translator-v2_5_1.html，另存新文件，不覆盖当前已经运行正常的 v2.5。无需安装 Node、Python 或开发环境。
2. 打开新文件，确认页面版本是 v2.5.1。如果在旧页面仍能看到原查询，请自行保存需要的导出；新文件不会自动继承旧标签页的输入、结果或导入状态。
3. 在新页面重新选择原来同一目录下的 normalization-summary.json 和 normalized-products.jsonl。数据格式未变，不必为了本次语法更新重新下载数据库或重跑转换器。原目录没有收录的字段不能由本次网页升级自动补全。
4. 粘贴同目录“客户描述测试.txt”中的七行到“描述 → 村田料号”，默认应用仍为民用设备 / 工业设备，点击查询。
5. 每行应识别封装、温度特性、容值、精度、电压；带 H 的行按标称高度筛选。RO 作为待确认要求显示，不再以“暂不能识别 CAP/CH/H/RO”中断查询。是否有候选、候选数量取决于你已导入的数据，不能固定承诺。
6. 原始七条都有 RO，因此即使其他参数相符，也只标“部分参数匹配”。含 RO 的正常生产记录仍可以查看、选择及导出，复制料号不表示 RO 已确认。后续拿到 RO 定义后再补相应条件校验。
7. 试导出一次 Excel 或 CSV，确认原输入、原表行号、RO 提示和新增高度列完整。两模式切换、手动清除、应用筛选和批量功能沿用 v2.5。
8. 传输后可用 PowerShell 的 Get-FileHash 检查 HTML SHA256，与同目录 SHA256SUMS.txt 对照。复制邮件正文曾造成引号和编码变化，因此应使用公司允许且能保留原文件字节的渠道；不要以能打开代替完整性校验。

本机完成 150 项测试、类型检查、H5 和独立 HTML 构建。新增测试覆盖用户原始七行、标称/最大厚度区别、不接受更薄替代、缺少高度、冲突/未知词、RO 的部分匹配与导出提示。本机测试数据是合成记录，不是公司产品数据；实际公司页面与数据验收仍需按上述步骤执行。
